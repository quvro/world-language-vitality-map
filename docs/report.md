# 世界语言赛博活力图谱 — 项目报告

> 课程：数据可视化与人机交互
> 数据规模：**157,736 行**（要求 ≥ 10,000，超出约 15.8 倍）
> 在线演示：`pnpm dev` 后打开 http://127.0.0.1:5173/
> 仓库：https://github.com/quvro/world-language-vitality-map

---

## 1. 这个项目在回答什么

全球约有 7,000 种语言。但在互联网上，只有约 360 种拥有维基百科版本；
而 AI 大模型真正"说得好"的语言，两只手数得过来。

我们把三种本不相干的数据叠在一起，回答一个具体问题：

> **什么样的语言，正在数字化的浪潮里被抛下？**

这里的"活力"必须说清楚：**本项目所有叫"活力"的数字都来自维基百科，
它衡量的是「数字关注度」，不是语言学意义上的「语言活力」。**
两者恰好高度相关，但也恰好不相等 —— 这个张力本身就是项目想讲的东西。

## 2. 数据来源

| # | 来源 | 接口 / 形式 | 拿到了什么 | 规模 |
|---|---|---|---|---|
| 1 | **WALS Online**（世界语言结构地图集） | CLDF 的 6 个 CSV | 语言的语法特征、坐标、语系归属 | 2,662 门语言 × 192 特征 → **76,475** 条特征值 |
| 2 | **Wikimedia REST API** | `wikimedia.org/api/rest_v1` | 每个维基语言版本的**月度浏览量**与**编辑量** | 135 个月（2015-07 ~ 2026-09）→ **65,161** 条时间序列 |
| 3 | **Wikidata** | SPARQL endpoint | ISO 639-1 ↔ 639-3 映射、宏观语言成员、UNESCO 濒危等级、中文名称 | 185 组 ISO 映射；2,394 条 UNESCO 等级；5,761 条中文名 |
| 4 | **Glottolog** | CLDF `values.csv`（21 MB） | **AES 濒危等级**、描写深度（`med`）、描写文献清单（`medovertime`） | **8,872** 条濒危记录；9,317 条描述深度；**9,302** 份文献清单 |
| 5 | **Wikimedia sitematrix** | `meta.wikimedia.org/w/api.php` | 每个语言版本拥有哪些维基项目（词典/文库/新闻…） | 374 个语言版本 |

**为什么是这几个源**：WALS 给"结构"，Wikimedia 给"数字在场"，Glottolog/UNESCO 给"语言学上的生存状况"。
三者正好对应三个不同学科的口径，交叉起来才能验证结论不是某一个数据集的偏差。

## 3. 我们是怎么采集的

### 3.1 管道结构

七个脚本，**按顺序执行、全部幂等**（重复运行会跳过已完成的部分）：

```
01_fetch_sources.py          WALS 六表 + ISO/宏观语言映射          ~1 分钟
02_fetch_wikimedia.py        月度浏览量/编辑量（可中断续抓）        ~20 分钟
03_build_dataset.py          构建 SQLite 与前端 JSON                ~30 秒
04_fetch_zh_labels.py        中文名称（Wikidata）                   ~4 分钟
05_fetch_endangerment.py     UNESCO 濒危等级（Wikidata P1999）
06_fetch_aes.py              Glottolog AES（覆盖面更大，优先使用）   ~15 秒
07_fetch_digital_presence.py 维基项目数 + 描写文献清单               ~2 秒
check_dataset.py             完整性自检
```

数据落地为 SQLite（`data/processed/language_vitality.db`），同时导出前端直接读取的 JSON。

### 3.2 采集过程中真正花时间的地方

这些不是"跑通脚本"就完事的，每一条都是踩出来的：

**① 跨源关联是三跳的，不是一跳。**
维基语言版本用 ISO 639-1 码（`zh`、`en`），WALS 用 ISO 639-3（`zho`、`eng`）。
而且 `zh / ar / fa / sw / ms` 这些**宏观语言**的码在 WALS 里根本不存在 ——
它们只出现在成员变体上。所以做了三跳回退：
直接命中 → ISO 639-1 转 639-3 → Wikidata 宏观语言成员（`P279`，**单层，不用传递闭包**）。
用 `P279+` 会把 `ar → mlt`（马耳他语）也算进来，实测过，所以放弃。
最终 364 个维基版本中 **271 个可关联**。

**② 七个语言版本的域名是猜不出来的。**
维基的域名并不总等于语言码：`yue` 在 `zh-yue.wikipedia.org`、
`nan` 在 `zh-min-nan`、`lzh` 在 `zh-classical`、`gsw` 在 `als`、
`rup` 在 `roa-rup`、`sgs` 在 `bat-smg`、`vro` 在 `fiu-vro`。
早期直接拼 `${code}.wikipedia.org` 会让这七个版本**静默 404**，
看起来像"这些语言没有数据"。改为从 sitematrix 读真实 URL。

**③ 限流要按它给的节奏退避。**
Wikimedia 在 0.2 秒间隔下大面积返回 429，改成 1.5 秒 + 尊重 `Retry-After`。
Wikidata 更严格（1 请求/分钟，`Retry-After` 最长 1000 秒），所以 04/05 各自只需要几次查询。
另外 Wikidata 的 SPARQL 不支持 `SERVICE wikibase:label` 叠加 `OPTIONAL`（会 400），
只能改用 `rdfs:label` + `FILTER(lang(?x)="en")`。

**④ 一个 WALS 条目会被多个维基版本认领。**
实测 4 例：`aze` ← `az` + `azb`（南阿塞拜疆语）、`ind` ← `id` + `ms`（马来语）、
`srb` ← 上/下索布语、`knr` ← `knc` + `kr`。
时间序列按 wals_id 存，于是同月有两行，而活力指标是
`groupby("wals_id").head(3).mean()` —— **把两个不相干的维基混在一起算**。
这个 bug 直接污染了增长榜：修复后印尼语从 −47.6% 变成 −51.7%。
修法是每个条目只保留一个主版本，排序依据依次是
① 与 WALS 主 ISO 码一致 ② **是否为 ISO 639-1 码（两字母）**
③ 跳数 ④ 总浏览量。第二条是决定性的：变体版用三字母（`azb`、`knc`），
语言主体版本才拿得到两字母（`az`、`id`）。

**⑤ AES 与 UNESCO 是两套 6 级量表，但可以合并。**
UNESCO 名录**只收濒危语言**（2,593 条里只有 82 条"safe"），覆盖 41.9%；
Glottolog AES 给所有语言都标了级，覆盖 97.3%。两者能 1:1 对应，
所以合并成一个量表（**AES 优先、UNESCO 补缺**），覆盖 2,614 / 2,662 = **98.2%**。

**⑥ Glottolog 的 21 MB 文件下载不下来。**
`raw.githubusercontent.com` 不通，jsDelivr 有 20 MB 上限，而 `values.csv` 是 21.4 MB。
最后走 GitHub 的 **blob API**（base64 编码返回，支持 100 MB），约 12 秒拿到。

## 4. 数据规模与结构

九张表，**157,736 行**：

| 表 | 行数 | 说明 |
|---|---|---|
| `dim_language` | 3,573 | 语言维表（导出前端时剔除 911 条语系层级占位行 → **2,662 门真语言**） |
| `fact_language_feature` | 76,475 | 语言 × 语法特征的事实表 |
| `fact_language_timeseries` | 65,161 | 语言 × 月份 × 指标（浏览量/编辑量） |
| `dim_endangerment` | 8,872 | 濒危等级。**AES 8,672 条 + 仅 UNESCO 独有的 200 条**（UNESCO 原表 2,394 条，与 AES 重叠部分被 AES 覆盖） |
| `feature_vector` | 2,660 | 宽表：2,660 语言 × 192 特征（**填充率 15.0%**） |
| `dim_wiki_edition` | 364 | 维基语言版本与关联情况 |
| `dim_genealogy` | 254 | 语系 |
| `dim_feature` | 192 | 语法特征 |
| `xref_iso` | 185 | ISO 639-1 ↔ 639-3 映射 |

**设计要点**：主键用 `wals_id` 而不是 `glottocode` ——
WALS 是"变体级"（同一种语言的不同变体分开收录），一个 Glottocode
最多对应 11 个变体（如巴斯克语 `basq1248`），用 Glottocode 当主键会合并掉这些变体。

## 5. 目前的视图

六个视图，全部**只读同一个 Pinia store、互不直接调用** ——
任一处选中或筛选，全局同步。顶栏可在**故事模式**（8 步引导）与**探索模式**之间切换。

| 视图 | 回答什么问题 | 形式 |
|---|---|---|
| **① 地图** | 这些语言在哪里？谁在数字空间活着？ | ECharts geo + 手写 SVG。点大小**随时间轴变化**；底图可在「密度块／逐点」之间切换；选中一门语言会画出它的**语系星群**（同族连线 + 凸包轮廓 + 浅强调色底圈） |
| **② 活力变化** | 十年里谁在退、谁在进？ | 增长榜 + 趋势散点 |
| **③ 条件对比** | 语法结构不同的语言，数字处境有差异吗？ | 按特征取值分组，比较"数字在场率" |
| **④ 记录缺口** | **数据集本身**有多不完整？ | Canvas 密度矩阵（2,660 × 192）+ 双重缺席柱状图 |
| **⑤ 濒危 × 关注** | 语言学上的濒危程度，和数字空间的存在性对得上吗？ | 散点 + 缺席柱状图 + 四类"值得关注的语言" |
| **⑥ 流向** | 语言正从哪个语系流向"没有数字入口"？ | 桑基图（语系 → 濒危等级 → 有无维基） |

**交互设计**：
- 底部**自然语言提问**（接入大模型）：一句话 → 结构化意图 → 写入 store → 全局联动 → 基于真实筛选结果生成解释
- **URL 状态分享**：当前画面编码进地址栏（两个条件只有 17 字符：`?area=Africa&end=5`）
- **故事模式**：8 步线性叙事，每步自动切换视图与筛选；**文案里的数字全部实时算出**，不会过期

## 6. 本项目的价值

### 6.1 学术价值：三个独立维度交叉验证同一件事

如果只看一个数据集，"记录少的语言也没有维基"完全可能是同一个偏差造成的。
所以我们用了**三套互不相干的记录口径**，看结论会不会散掉：

| 维度 | 来源 | 从"最差"到"最好"的有维基比例 |
|---|---|---|
| WALS 记录完整度 | WALS（语法特征数） | 5.6% → **92.9%** |
| 描述深度 | Glottolog `med` | 0.0% → **17.6%** |
| 描写文献数 | Glottolog `medovertime` | 2.5% → **30.8%** |
| 濒危等级 | AES / UNESCO | 0.9% → **18.0%** |

**四套口径、同一个方向。** 这说明"被记录得越少 → 在数字世界越不可见"
不是某个数据集的 artifact。

### 6.2 最有冲击力的三个发现

**① 双重缺席。** 2,662 门语言里只有 **267 门（10.0%）** 有维基百科版本。
而"有没有维基版本"和"被 WALS 记录了多少特征"几乎同向：
记录 <30 个特征的语言只有 **5.6%** 有版本，记录 ≥150 个特征的则有 **92.9%**。

**② 这不是某几个语系的问题。** 桑基图上，
**每个语系（语言数 ≥20 的共 15 个）都是"无维基"占多数**，全局 89.9% 没有。
从任何一个语系出发，最宽的流带最后都汇入同一侧。

**③ 但数字空间也在"续命"。** 已灭绝档的 223 门语言里只有 2 门有维基版本 ——
可这两门正是**康沃尔语**（最后一位母语者 1777 年去世）与**马恩岛语**（1974 年）。
它们作为口语已经消失，在数字空间里却**仍在增长**（十年 +2003%、+116%，
康沃尔语当前月阅读量约 215 万）。
所以"数字缺席"不是单向的：它既能抛弃一门语言，也能替一门语言续命。

### 6.3 方法论价值：用浏览量而不是文章数

Kornai 在 *Digital Language Death*（PLOS ONE, 2013）里提出
"**No wikipedia, no ascent**"，并警告过 **"Potemkin wikipedia"** 问题 ——
瓦洛夫语维基文章数排第 37，但几乎全是机器生成的地理条目在刷数量。

**这就是本项目用「月度浏览量」而不是「文章数」作为代理的原因**：
文章数可以被机器人灌水，浏览量不行。这条辩护有明确的文献依据。

### 6.4 交互与工程价值

- **可复现**：七个幂等脚本 + 一次自检，从零到完整数据集约 25 分钟
- **可验证**：**17 个验证脚本**（含数据不变量审查、ECharts SSR 渲染验证、
  故事文案与数据一致性检查、凸包算法单元测试），全部能在 Node 里跑，无需浏览器
- **诚实的缺口记录**：报告里所有"做不到"的地方都写明了原因
  （ELCat 在 Cloudflare 后面抓不动、南岛语系跨 180° 经线画不出轮廓、
  WALS 的 `srb` 一行合并了两种语言）

## 7. 已知局限

1. **"活力"= 数字关注度，不等于语言活力。** 212 门有濒危等级但仍无维基版本的语言，
   可能只是"没人写维基"，而不是"没人说"。浏览量也不是使用者人数。
2. **维基百科本身有系统性偏差**：它偏向有写作传统、有网络接入、有志愿者社群的语言。
3. **2,395 门语言没有任何维基版本**，因此在任何时间序列视图里都是"缺席"而非"零"——
   我们刻意用视觉上的缺席表达它们，而不是画成 0，因为 0 会误导成"没人读"。
4. **WALS 的 `srb`（索布语）一行合并了上索布语与下索布语**，任何单一选择都是折中。
5. **数据本身的缺口**：`feature_vector` 只有 15.0% 的格子有值，
   特征覆盖率中位数只有 9.7%（对应 2,660 门语言中的 257 门）。
   所以"某门语言没有这个特征"和"没人研究过这门语言的这个特征"，在数据里长得一样。

## 8. 复现方式

```bash
# 数据（需要 Python 3.11+ 与 pandas，其余只用标准库）
python pipeline/01_fetch_sources.py
python pipeline/02_fetch_wikimedia.py       # 可中断续抓
python pipeline/03_build_dataset.py
python pipeline/04_fetch_zh_labels.py       # 可选
python pipeline/05_fetch_endangerment.py    # 可选
python pipeline/06_fetch_aes.py             # 可选
python pipeline/07_fetch_digital_presence.py
python pipeline/check_dataset.py

# 前端
cd web
pnpm install
pnpm dev            # http://127.0.0.1:5173/
pnpm typecheck      # vue-tsc
node preview/verify-*.mjs   # 17 个验证脚本
```

**网络可达性**（实测）：`api.github.com` ✅、`cdn.jsdelivr.net` ✅、
`wikimedia.org/api/rest_v1` ✅、`query.wikidata.org` ⚠️ 1 次/分钟、
`raw.githubusercontent.com` ❌。
